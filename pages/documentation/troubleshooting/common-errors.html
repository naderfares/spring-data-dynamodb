Common Errors and Solutions

This guide covers frequently encountered errors and their solutions.

Table of Contents

  1. TOC

Configuration Errors

AmazonDynamoDB Bean Not Found

Error:

No qualifying bean of type 'com.amazonaws.services.dynamodbv2.AmazonDynamoDB'

Cause: Missing DynamoDB client configuration.

Solution:

@Configuration
@EnableDynamoDBRepositories(basePackages = "com.example.repository")
public class DynamoDBConfig {

    @Bean
    public AmazonDynamoDB amazonDynamoDB() {
        return AmazonDynamoDBClientBuilder.standard()
            .withCredentials(new DefaultAWSCredentialsProviderChain())
            .withRegion(Regions.US_EAST_1)
            .build();
    }

    @Bean
    public DynamoDBMapperConfig dynamoDBMapperConfig() {
        return DynamoDBMapperConfig.DEFAULT;
    }

    @Bean
    public DynamoDBMapper dynamoDBMapper(AmazonDynamoDB amazonDynamoDB,
                                          DynamoDBMapperConfig config) {
        return new DynamoDBMapper(amazonDynamoDB, config);
    }
}

AWS Credentials Not Found

Error:

Unable to load AWS credentials from any provider in the chain

Cause: AWS credentials are not configured properly.

Solution 1: Environment Variables

export AWS_ACCESS_KEY_ID=your_access_key
export AWS_SECRET_ACCESS_KEY=your_secret_key
export AWS_REGION=us-east-1

Solution 2: AWS Credentials File

Create ~/.aws/credentials:

[default]
aws_access_key_id = your_access_key
aws_secret_access_key = your_secret_key

And ~/.aws/config:

[default]
region = us-east-1

Solution 3: Application Properties

amazon.dynamodb.accesskey=your_access_key
amazon.dynamodb.secretkey=your_secret_key
amazon.dynamodb.region=us-east-1

@Configuration
public class DynamoDBConfig {

    @Value("${amazon.dynamodb.accesskey}")
    private String amazonAWSAccessKey;

    @Value("${amazon.dynamodb.secretkey}")
    private String amazonAWSSecretKey;

    @Value("${amazon.dynamodb.region}")
    private String amazonAWSRegion;

    @Bean
    public AmazonDynamoDB amazonDynamoDB() {
        BasicAWSCredentials awsCredentials =
            new BasicAWSCredentials(amazonAWSAccessKey, amazonAWSSecretKey);

        return AmazonDynamoDBClientBuilder.standard()
            .withCredentials(new AWSStaticCredentialsProvider(awsCredentials))
            .withRegion(amazonAWSRegion)
            .build();
    }
}

Entity Mapping Errors

No Hash Key Found

Error:

No method annotated with @DynamoDBHashKey found in class

Cause: Entity class is missing a hash key annotation.

Solution:

@DynamoDBTable(tableName = "User")
public class User {

    private String id;
    private String name;

    @DynamoDBHashKey
    @DynamoDBAutoGeneratedKey
    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    @DynamoDBAttribute
    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

Multiple Hash Keys Defined

Error:

Multiple methods annotated with @DynamoDBHashKey found

Cause: More than one field or method is annotated with @DynamoDBHashKey.

Solution: Ensure only one hash key per entity:

@DynamoDBTable(tableName = "Order")
public class Order {

    private String orderId;      // Hash key
    private String orderDate;    // Range key
    private String customerId;   // Regular attribute

    @DynamoDBHashKey
    public String getOrderId() {
        return orderId;
    }

    @DynamoDBRangeKey
    public String getOrderDate() {
        return orderDate;
    }

    @DynamoDBAttribute
    public String getCustomerId() {
        return customerId;
    }

    // setters...
}

Composite ID Not Properly Configured

Error:

Could not extract id from entity

Cause: Composite key (hash + range) not properly mapped.

Solution 1: Using @DynamoDBHashKey and @DynamoDBRangeKey

@DynamoDBTable(tableName = "Order")
public class Order {

    private String customerId;
    private String orderDate;

    @DynamoDBHashKey
    public String getCustomerId() {
        return customerId;
    }

    @DynamoDBRangeKey
    public String getOrderDate() {
        return orderDate;
    }

    // setters...
}

Solution 2: Using Composite ID Class

// ID class
public class OrderId implements Serializable {
    private String customerId;
    private String orderDate;

    public OrderId() {}

    public OrderId(String customerId, String orderDate) {
        this.customerId = customerId;
        this.orderDate = orderDate;
    }

    @DynamoDBHashKey
    public String getCustomerId() {
        return customerId;
    }

    @DynamoDBRangeKey
    public String getOrderDate() {
        return orderDate;
    }

    // setters, equals, hashCode...
}

// Entity class
@DynamoDBTable(tableName = "Order")
public class Order {

    private OrderId orderId;
    private Double amount;

    @Id
    public OrderId getOrderId() {
        return orderId;
    }

    @DynamoDBAttribute
    public Double getAmount() {
        return amount;
    }

    // setters...
}

Table Errors

Table Not Found

Error:

Requested resource not found: Table: User not found

Cause: The DynamoDB table doesn’t exist in your AWS account/region.

Solution 1: Create Table Manually

Using AWS Console or CLI:

aws dynamodb create-table \
    --table-name User \
    --attribute-definitions \
        AttributeName=id,AttributeType=S \
    --key-schema \
        AttributeName=id,KeyType=HASH \
    --provisioned-throughput \
        ReadCapacityUnits=5,WriteCapacityUnits=5

Solution 2: Create Table Programmatically

@Bean
public CommandLineRunner initializeTables(AmazonDynamoDB amazonDynamoDB,
                                           DynamoDBMapper mapper) {
    return args -> {
        CreateTableRequest tableRequest = mapper
            .generateCreateTableRequest(User.class);
        tableRequest.setProvisionedThroughput(
            new ProvisionedThroughput(5L, 5L));

        try {
            amazonDynamoDB.createTable(tableRequest);

            // Wait for table to become active
            DynamoDB dynamoDB = new DynamoDB(amazonDynamoDB);
            Table table = dynamoDB.getTable("User");
            table.waitForActive();
        } catch (ResourceInUseException e) {
            // Table already exists
        }
    };
}

Solution 3: Using DynamoDB Local

For local development:

@Bean
public AmazonDynamoDB amazonDynamoDB() {
    return AmazonDynamoDBClientBuilder.standard()
        .withEndpointConfiguration(
            new AwsClientBuilder.EndpointConfiguration(
                "http://localhost:8000", "us-east-1"))
        .withCredentials(new AWSStaticCredentialsProvider(
            new BasicAWSCredentials("dummy", "dummy")))
        .build();
}

Table Name Mismatch

Error:

Requested resource not found: Table: user not found

Cause: Table name doesn’t match between entity annotation and actual table.

Solution:

// Ensure @DynamoDBTable matches actual table name (case-sensitive)
@DynamoDBTable(tableName = "User")  // Must match exactly
public class User {
    // ...
}

Or use table name prefix/override:

@Bean
public DynamoDBMapperConfig dynamoDBMapperConfig() {
    DynamoDBMapperConfig.TableNameOverride tableNameOverride =
        DynamoDBMapperConfig.TableNameOverride
            .withTableNamePrefix("dev_");

    return DynamoDBMapperConfig.builder()
        .withTableNameOverride(tableNameOverride)
        .build();
}

DynamoDB Local Issues

SQLite4Java Library Not Found

Error:

java.lang.UnsatisfiedLinkError: no sqlite4java-osx-x86_64 in java.library.path

Cause: SQLite native libraries required by DynamoDB Local are not in the Java library path.

Solution 1: Maven Configuration

Add to your pom.xml:

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-dependency-plugin</artifactId>
            <executions>
                <execution>
                    <id>copy-native-libs</id>
                    <phase>process-test-resources</phase>
                    <goals>
                        <goal>copy-dependencies</goal>
                    </goals>
                    <configuration>
                        <outputDirectory>${project.build.directory}/lib</outputDirectory>
                        <includeArtifactIds>
                            sqlite4java,sqlite4java-win32-x86,sqlite4java-win32-x64,
                            sqlite4java-osx,sqlite4java-linux-i386,sqlite4java-linux-amd64
                        </includeArtifactIds>
                        <stripVersion>true</stripVersion>
                    </configuration>
                </execution>
            </executions>
        </plugin>
    </plugins>
</build>

Solution 2: System Property

@BeforeAll
public static void setupDynamoDBLocal() {
    System.setProperty("sqlite4java.library.path", "target/lib");
}

Solution 3: JVM Argument

mvn test -Dsqlite4java.library.path=target/lib

DynamoDB Local Not Starting

Error:

Unable to connect to local DynamoDB at http://localhost:8000

Cause: DynamoDB Local server is not running.

Solution 1: Start DynamoDB Local Manually

java -Djava.library.path=./DynamoDBLocal_lib -jar DynamoDBLocal.jar -sharedDb

Solution 2: Use Docker

docker run -p 8000:8000 amazon/dynamodb-local

Solution 3: Embedded DynamoDB for Tests

Add dependency:

<dependency>
    <groupId>com.amazonaws</groupId>
    <artifactId>DynamoDBLocal</artifactId>
    <version>1.21.1</version>
    <scope>test</scope>
</dependency>

Start in tests:

@TestConfiguration
public class DynamoDBLocalConfig {

    private static DynamoDBProxyServer server;

    @Bean
    public AmazonDynamoDB amazonDynamoDB() throws Exception {
        System.setProperty("sqlite4java.library.path", "target/lib");

        server = ServerRunner.createServerFromCommandLineArgs(
            new String[]{"-inMemory", "-port", "8000"});
        server.start();

        return AmazonDynamoDBClientBuilder.standard()
            .withEndpointConfiguration(
                new AwsClientBuilder.EndpointConfiguration(
                    "http://localhost:8000", "us-east-1"))
            .withCredentials(new AWSStaticCredentialsProvider(
                new BasicAWSCredentials("dummy", "dummy")))
            .build();
    }

    @PreDestroy
    public void shutdown() throws Exception {
        if (server != null) {
            server.stop();
        }
    }
}

Repository Errors

No Property Found for Type

Error:

No property 'email' found for type 'User'

Cause: Query method references a property that doesn’t exist or isn’t properly mapped.

Solution:

@DynamoDBTable(tableName = "User")
public class User {

    private String id;
    private String email;  // Property must exist

    @DynamoDBHashKey
    public String getId() {
        return id;
    }

    @DynamoDBAttribute(attributeName = "email")  // Explicitly map if needed
    public String getEmail() {
        return email;
    }

    // setters...
}

public interface UserRepository extends CrudRepository<User, String> {
    List<User> findByEmail(String email);  // Now properly mapped
}

Invalid Query Method Signature

Error:

Could not create query for method findByName

Cause: Query method signature doesn’t follow Spring Data naming conventions or uses unsupported operations.

Solution:

// ✅ Valid query methods
List<User> findByName(String name);
List<User> findByNameAndEmail(String name, String email);
Optional<User> findById(String id);
Page<User> findByStatus(String status, Pageable pageable);

// ❌ Invalid - DynamoDB doesn't support OR in query methods
// Use scan with @EnableScan instead
List<User> findByNameOrEmail(String name, String email);

// ❌ Invalid - Use findByIdAndDate for composite keys
List<Order> findByCustomerIdAndOrderDate(String customerId, String orderDate);
