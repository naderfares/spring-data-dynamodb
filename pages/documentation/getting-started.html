Getting Started with Spring Data DynamoDB

This guide will help you get started with Spring Data DynamoDB in under 15 minutes. By the end, you’ll have a working Spring Boot application performing CRUD operations on DynamoDB.

Prerequisites

Before you begin, ensure you have:

  • Java 17 or higher installed
  • Maven 3.6+ or Gradle 7.0+
  • Spring Boot 3.x (3.5+ recommended)
  • AWS Account with DynamoDB access (or use DynamoDB Local for development)
  • AWS Credentials configured (for production) or DynamoDB Local installed (for development)

Step 1: Add Dependencies

Maven

Add the Spring Data DynamoDB dependency to your pom.xml:

<dependencies>
    <!-- Spring Data DynamoDB -->
    <dependency>
        <groupId>io.github.naderfares</groupId>
        <artifactId>spring-data-dynamodb</artifactId>
        <version>6.0.11</version>
    </dependency>

    <!-- AWS SDK DynamoDB (managed by Spring Data DynamoDB) -->
    <dependency>
        <groupId>com.amazonaws</groupId>
        <artifactId>aws-java-sdk-dynamodb</artifactId>
    </dependency>

    <!-- Spring Boot Starter Web (for REST APIs) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>

Gradle

Add to your build.gradle:

dependencies {
    implementation 'io.github.naderfares:spring-data-dynamodb:6.0.11'
    implementation 'com.amazonaws:aws-java-sdk-dynamodb'
    implementation 'org.springframework.boot:spring-boot-starter-web'
}

Step 2: Configure Application Properties

Create or update your application.yml with AWS configuration:

For AWS DynamoDB (Production) 

spring:
  application:
    name: dynamodb-demo

# AWS Configuration
amazon:
  dynamodb:
    endpoint: https://dynamodb.us-east-1.amazonaws.com
    region: us-east-1
    # Credentials will be loaded from:
    # 1. Environment variables (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY)
    # 2. AWS credentials file (~/.aws/credentials)
    # 3. IAM role (when running on EC2/ECS/Lambda)

# Optional: Enable auto table creation (development only)
spring.data.dynamodb.entity2ddl.auto: create

For DynamoDB Local (Development) 

spring:
  application:
    name: dynamodb-demo

# DynamoDB Local Configuration
amazon:
  dynamodb:
    endpoint: http://localhost:8000
    region: us-east-1
    accessKey: local
    secretKey: local

# Auto-create tables on startup
spring.data.dynamodb.entity2ddl.auto: create

Note: The spring.data.dynamodb.entity2ddl.auto=create property automatically creates tables based on your entities. Use this only in development environments.

Step 3: Create Your First Entity

Create a Product entity with a hash key:

package com.example.demo.model;

import com.amazonaws.services.dynamodbv2.datamodeling.DynamoDBAutoGeneratedKey;
import com.amazonaws.services.dynamodbv2.datamodeling.DynamoDBHashKey;
import com.amazonaws.services.dynamodbv2.datamodeling.DynamoDBTable;

@DynamoDBTable(tableName = "Product")
public class Product {

    private String id;
    private String name;
    private String description;
    private Double price;
    private Integer quantity;

    // Default constructor required by DynamoDB mapper
    public Product() {
    }

    public Product(String name, String description, Double price, Integer quantity) {
        this.name = name;
        this.description = description;
        this.price = price;
        this.quantity = quantity;
    }

    @DynamoDBHashKey(attributeName = "id")
    @DynamoDBAutoGeneratedKey
    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getDescription() {
        return description;
    }

    public void setDescription(String description) {
        this.description = description;
    }

    public Double getPrice() {
        return price;
    }

    public void setPrice(Double price) {
        this.price = price;
    }

    public Integer getQuantity() {
        return quantity;
    }

    public void setQuantity(Integer quantity) {
        this.quantity = quantity;
    }

    @Override
    public String toString() {
        return "Product{" +
                "id='" + id + '\'' +
                ", name='" + name + '\'' +
                ", price=" + price +
                ", quantity=" + quantity +
                '}';
    }
}

Key Annotations Explained:

  • @DynamoDBTable(tableName = "Product"): Specifies the DynamoDB table name
  • @DynamoDBHashKey: Marks the field as the partition key (primary key)
  • @DynamoDBAutoGeneratedKey: Auto-generates UUID values for the key
  • Default constructor: Required by AWS DynamoDB Mapper for object instantiation

Step 4: Create Your First Repository

Create a repository interface extending CrudRepository:

package com.example.demo.repository;

import com.example.demo.model.Product;
import org.socialsignin.spring.data.dynamodb.repository.EnableScan;
import org.springframework.data.repository.CrudRepository;

import java.util.List;
import java.util.Optional;

public interface ProductRepository extends CrudRepository<Product, String> {

    // Query by name - requires scan since 'name' is not a key
    @EnableScan
    Optional<Product> findByName(String name);

    // Find all products - requires scan
    @EnableScan
    @Override
    List<Product> findAll();

    // Find by price range - requires scan
    @EnableScan
    List<Product> findByPriceBetween(Double minPrice, Double maxPrice);

    // Delete all - requires scan
    @EnableScan
    @Override
    void deleteAll();
}

Important: Methods that query on non-key attributes or perform table scans require the @EnableScan annotation. This is a safety mechanism to prevent accidental expensive operations.

Step 5: Configure DynamoDB

Create a configuration class to set up DynamoDB connectivity:

package com.example.demo.config;

import com.amazonaws.auth.AWSCredentials;
import com.amazonaws.auth.AWSCredentialsProvider;
import com.amazonaws.auth.AWSStaticCredentialsProvider;
import com.amazonaws.auth.BasicAWSCredentials;
import com.amazonaws.client.builder.AwsClientBuilder;
import com.amazonaws.services.dynamodbv2.AmazonDynamoDB;
import com.amazonaws.services.dynamodbv2.AmazonDynamoDBClientBuilder;
import org.socialsignin.spring.data.dynamodb.repository.config.EnableDynamoDBRepositories;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableDynamoDBRepositories(basePackages = "com.example.demo.repository")
public class DynamoDBConfig {

    @Value("${amazon.dynamodb.endpoint}")
    private String dynamoDBEndpoint;

    @Value("${amazon.dynamodb.region}")
    private String dynamoDBRegion;

    @Value("${amazon.dynamodb.accessKey:}")
    private String accessKey;

    @Value("${amazon.dynamodb.secretKey:}")
    private String secretKey;

    @Bean
    public AmazonDynamoDB amazonDynamoDB() {
        AmazonDynamoDBClientBuilder builder = AmazonDynamoDBClientBuilder.standard();

        // Use local credentials if provided (for DynamoDB Local)
        if (!accessKey.isEmpty() && !secretKey.isEmpty()) {
            builder.withCredentials(amazonAWSCredentialsProvider());
        }

        // Configure endpoint and region
        builder.withEndpointConfiguration(
            new AwsClientBuilder.EndpointConfiguration(dynamoDBEndpoint, dynamoDBRegion)
        );

        return builder.build();
    }

    private AWSCredentialsProvider amazonAWSCredentialsProvider() {
        return new AWSStaticCredentialsProvider(amazonAWSCredentials());
    }

    private AWSCredentials amazonAWSCredentials() {
        return new BasicAWSCredentials(accessKey, secretKey);
    }
}

Configuration Highlights:

  • @EnableDynamoDBRepositories: Activates Spring Data DynamoDB repositories
  • basePackages: Specifies where to scan for repository interfaces
  • Supports both AWS credentials and default credential chain
  • Configurable endpoint for local development or production

Step 6: Perform CRUD Operations

Create a simple REST controller to demonstrate CRUD operations:

package com.example.demo.controller;

import com.example.demo.model.Product;
import com.example.demo.repository.ProductRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Optional;

@RestController
@RequestMapping("/api/products")
public class ProductController {

    @Autowired
    private ProductRepository productRepository;

    // Create a new product
    @PostMapping
    public Product createProduct(@RequestBody Product product) {
        return productRepository.save(product);
    }

    // Get all products
    @GetMapping
    public List<Product> getAllProducts() {
        return productRepository.findAll();
    }

    // Get product by ID
    @GetMapping("/{id}")
    public ResponseEntity<Product> getProductById(@PathVariable String id) {
        Optional<Product> product = productRepository.findById(id);
        return product.map(ResponseEntity::ok)
                      .orElse(ResponseEntity.notFound().build());
    }

    // Update product
    @PutMapping("/{id}")
    public ResponseEntity<Product> updateProduct(@PathVariable String id,
                                                  @RequestBody Product productDetails) {
        Optional<Product> productOpt = productRepository.findById(id);

        if (productOpt.isPresent()) {
            Product product = productOpt.get();
            product.setName(productDetails.getName());
            product.setDescription(productDetails.getDescription());
            product.setPrice(productDetails.getPrice());
            product.setQuantity(productDetails.getQuantity());

            Product updatedProduct = productRepository.save(product);
            return ResponseEntity.ok(updatedProduct);
        }

        return ResponseEntity.notFound().build();
    }

    // Delete product
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteProduct(@PathVariable String id) {
        if (productRepository.existsById(id)) {
            productRepository.deleteById(id);
            return ResponseEntity.ok().build();
        }
        return ResponseEntity.notFound().build();
    }

    // Search by name
    @GetMapping("/search")
    public ResponseEntity<Product> searchByName(@RequestParam String name) {
        Optional<Product> product = productRepository.findByName(name);
        return product.map(ResponseEntity::ok)
                      .orElse(ResponseEntity.notFound().build());
    }

    // Find by price range
    @GetMapping("/price-range")
    public List<Product> getProductsByPriceRange(@RequestParam Double min,
                                                   @RequestParam Double max) {
        return productRepository.findByPriceBetween(min, max);
    }
}

Step 7: Running with DynamoDB Local

For local development, use DynamoDB Local:

Download and Run DynamoDB Local 

# Download DynamoDB Local
wget https://s3.us-west-2.amazonaws.com/dynamodb-local/dynamodb_local_latest.tar.gz

# Extract
tar -xzf dynamodb_local_latest.tar.gz

# Run DynamoDB Local
java -Djava.library.path=./DynamoDBLocal_lib -jar DynamoDBLocal.jar -sharedDb -port 8000

Using Docker (Recommended) 

# Run DynamoDB Local in Docker
docker run -p 8000:8000 amazon/dynamodb-local

Verify DynamoDB Local is Running 

# List tables (should be empty initially)
aws dynamodb list-tables --endpoint-url http://localhost:8000 --region us-east-1

Common Pitfalls and Tips

1. Missing @EnableScan Annotation

Problem: UnsupportedOperationException: Scan not enabled

Solution: Add @EnableScan to repository methods that query non-key attributes:

@EnableScan
List<Product> findByName(String name);

2. Default Constructor Missing

Problem: InstantiationException when loading entities

Solution: Always provide a default no-args constructor:

public Product() {
    // Required by DynamoDB mapper
}

3. Getter/Setter Method Names

Problem: DynamoDB mapper cannot access fields

Solution: Follow JavaBean conventions for getter/setter names:

// Correct
public String getName() { return name; }
public void setName(String name) { this.name = name; }

4. Table Auto-Creation Not Working

Problem: Tables not created automatically

Solution: Ensure spring.data.dynamodb.entity2ddl.auto=create is set in application.yml

Warning: Use auto-creation only in development. In production, create tables manually or via Infrastructure as Code (CloudFormation, Terraform).

5. AWS Credentials Not Found

Problem: Unable to load AWS credentials

Solution: Configure credentials using one of these methods:

  1. Environment Variables: 
    export AWS_ACCESS_KEY_ID=your_access_key
export AWS_SECRET_ACCESS_KEY=your_secret_key
  2. AWS Credentials File (~/.aws/credentials): 
    [default]
aws_access_key_id = your_access_key
aws_secret_access_key = your_secret_key
  3. IAM Role: When running on AWS (EC2, ECS, Lambda), use IAM roles

6. Performance Issues with Scans

Problem: Slow queries and high costs

Solution: Use Global Secondary Indexes (GSI) for frequently queried non-key attributes:

@DynamoDBIndexHashKey(globalSecondaryIndexName = "name-index")
public String getName() {
    return name;
}

Learn more: DynamoDB GSI Example

7. Null Attribute Values

Problem: DynamoDB doesn’t support null values

Solution: Use Optional or default values:

public Optional<String> getDescription() {
    return Optional.ofNullable(description);
}

Production Considerations

Security Best Practices

  1. Never hardcode credentials - Use IAM roles or AWS Secrets Manager
  2. Use least privilege IAM policies - Grant only necessary DynamoDB permissions
  3. Enable encryption at rest - Use AWS KMS for table encryption
  4. Enable encryption in transit - Use HTTPS endpoints

Performance Optimization

  1. Use batch operations for bulk reads/writes: 
    List<Product> products = Arrays.asList(product1, product2, product3);
productRepository.saveAll(products);
  2. Implement pagination for large result sets: 
    Page<Product> page = productRepository.findAll(PageRequest.of(0, 20));
  3. Use projection expressions to fetch only required attributes: 
    @Query(fields = "id, name, price")
List<Product> findAllProjected();
  4. Cache frequently accessed data using Spring Cache or Redis

Learn more: Query Size Limits and Pageable

Monitoring and Logging

  1. Enable DynamoDB metrics in CloudWatch
  2. Monitor consumed capacity to optimize costs
  3. Set up alarms for throttling and errors
  4. Use X-Ray for distributed tracing
